# Interactions: what the game does and what DarkwoodMP shares

This file lists the things in Darkwood that a player or the world itself interacts with (doors, containers, traps, enemies, NPCs, the clock, night events, dreams, the player's own actions), the game methods that do it, and whether DarkwoodMP shares the result between the players' games. It was put together by reading the game's decompiled code and the mod's source; nothing here was tested in game unless a row says so, and rows marked "(read, not tested)" or "unverified" most need a check. The status words are **Shared** (the mod sends it; the mod file is named), **Partly** (some of it is sent; the row says what is missing), **Not shared** (it happens in one game only), and **Each player's own** (it belongs to one player on purpose: their inventory, character, UI or a separate place). Mod files are under `src/DarkwoodMP/`.

Background that many rows depend on:

- The host runs every enemy and animal (every `Character` without an `NPC`). On a joiner, each such character its own game makes is frozen and hidden, except in a separate location or a dream (`NetEnemies.LocalOnly`). So an enemy that a joiner's own game spawns (night spawns, scripted spawns, random events) never shows up or acts.
- NPCs (traders, quest characters, the wolf) run separately in every game. Only their story state and their death are shared.
- A joiner runs `Controller.refreshTime()` once for each minute of the host's clock (`World/TimeSync.cs`), so everything hung on the clock (dawn, dusk) also runs in each joiner's game. What the world rolls on the clock (night scenarios and events, day events, random objects, weather) is rolled on the host only and sent (`World/WorldEvents.cs`, gaps 2, 14, 30).
- Many enemy behaviours read `Player.Instance`, which on the host is always the host's player, never a joiner's proxy (`Combat/NetPlayerProxy.cs`). The mod swaps in the threat target only in `canSeeEnemy` (`Threat.PursuitTarget`) and in `attackPlayer`, and the nearest player or the enemy's target in the despawn and run-away checks of gap 17.
- "Puppet" is the other games' sprite copy of a player (`Sync/PlayerSnapshot.cs`, `Sync/RemotePlayer.cs`). "Proxy" is the host's stand-in for a joiner that the AI sees: position, rotation, `alive` and a collider, nothing else.

Where the three readings disagreed, the rows say so. The time skip was settled by checking the code: it can't be used at all (gap 16). Picking up dropped items was settled by a test: a click pickup wasn't shared, and now is (gap 20). The one on unlocking with a key or lockpick was settled by checking the code: it wasn't shared, and now is (gap 5).
