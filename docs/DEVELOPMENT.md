# Developing DarkwoodMP

- **Requirements:** the .NET SDK 8 or newer, and BepInEx installed in the game folder (the build references its DLLs and the game's).
- **Build:** `dotnet build src/DarkwoodMP -c Release` builds and copies the DLL into `<game>/BepInEx/plugins/DarkwoodMP/`. The game folder defaults to Steam's; override it with `-p:GameDir=/path/to/Darkwood`. `./pack.sh` builds the two release zips.
- **Tests:** `tools/run-test.sh <test>...` runs the real game against scripted Python players (`tools/tests/`), `tools/run-test.sh all` for every test. One game runs the whole list: the script starts it with `--dwmp-test-control PORT` and sends it each test's title (shown along the top of the screen, "Test (3/17): host-world - ..."), a reset back to the main menu, and the test's arguments. It plays a copy of your save, and checks after each test that your saves are unchanged and that there were no new exceptions. `tools/run-test.sh map` runs two real games instead: the host plays the test world (a copy of your save), the client is a second copy of the game made by `tools/setup-client-game.sh` in `~/.cache/darkwood-mp/client-game` with its own home folder, and they join over Direct on 127.0.0.1. Scripted steps (`tools/tests/map_scenario*.py`, `World/MapScenario*.cs`) have each player do one of everything that's shared and the reported bugs' cases; then both games dump their shared world (`World/StateDump.cs`) and `tools/tests/mapcompare.py` checks the two agree. The map test is split into parts that each run alone, in any order and with a fresh world each (`tools/run-test.sh map:ui map:knock`, `maps` for every part, `--list` for all of them, `--plan` to see what would run); a results table at the end gives each one's result, time, first failure and the command that reruns it. [MULTIPLAYER_TESTING_GUIDE.md](MULTIPLAYER_TESTING_GUIDE.md) says which part covers what and how long each takes (`maps` about 80 minutes).
- **Launch arguments** (used by the tests, also handy for always-on hosts):
  - `--dwmp-host` hosts Direct at once, and `--dwmp-join host:port` joins once the menu is up.
  - `--dwmp-continue N` loads your profile N, and `--dwmp-sandbox DIR` plays a copy of saves in DIR.
  - `--dwmp-password P` hosts with that password this time only (your setting is untouched).
  - Test hooks: `--dwmp-test-start-window` (opens the Start Game window; with `--dwmp-sandbox DIR` on a copy of the saves, `--dwmp-shots DIR` screenshots, `--dwmp-start N|new` then starts slot N or a new game, `--dwmp-start-host direct|steam` hosting it, `--dwmp-start-name NAME` naming it), `--dwmp-dummy`, `--dwmp-spawn TYPE`, `--dwmp-test-world`, `--dwmp-test-save N`, `--dwmp-test-death`, `--dwmp-test-reload N`, `--dwmp-test-menu N`, `--dwmp-test-client-actions`, `--dwmp-test-blast`, `--dwmp-steam-test`, `--dwmp-test-presence` (logs the Steam presence text every 5 s, even without Steam), `--dwmp-shots DIR`, `--dwmp-test-control PORT`, `--dwmp-test-menu-entry`, `--dwmp-solo-test DIR` (playing alone, with `--dwmp-continue N --dwmp-sandbox DIR`: the pause menu over the world, the Skills panel and a point spent, skill resets at the stove outside and in the morning, and a level taken at the stove, with screenshots), `--dwmp-screen WxH` (a window that size, for checking other screen shapes; with `--dwmp-shots DIR`, screenshots), `--dwmp-testworld` (starts the test world from the main menu; with `--dwmp-reset`, from a fresh copy; with `--dwmp-shots DIR`, screenshots of the area once it's built), `--dwmp-dump-prefabs` (once in a world, logs every prefab the save system knows, name and path).
  - Logging: `--dwmp-debug-world` (with the requests and verdicts), `--dwmp-debug-threat`.
  - Speed: `--dwmp-profile-load` times the game's loading code and logs the slowest parts; `--dwmp-verify-load` checks the faster grid lookup against the game's own (see `World/LoadSpeed.cs`); `--dwmp-profile-mod` logs what each part of the mod's per-frame work costs, every 10 seconds.

## Test world

For trying out what's shared without touching your own saves. It's a tool for testing the mod, so the panel only shows it when the game was started with a `--dwmp-test...` argument (as `tools/run-test.sh` does) or `--dwmp-testworld`. Then, in the main menu, the panel's *Test world* section has *Make and start a test world* (later *Start the test world*) and *Reset it*. It copies your saves into `BepInEx/cache/DarkwoodMP/testworld` and plays that copy through the same save redirect a joiner uses, so your own saves are never written; *Reset it* makes a fresh copy. The first time it loads, the game builds a test area of 21 labelled things around your character, out of the game's own pieces: containers and crates (one locked), a workbench, furniture to drag, a generator with two lamps on it, the saw, candles, a radio, a stove, traps, an exploding barrel, a gas bottle, broken glass, a larva egg, a patch of infection and the night trader. Each has a label over it saying what to try. Doors and windows aren't separate pieces in the game, so use the hideout's own. You get a kit (gasoline, matches, molotovs, flares, a torch, a lantern, a flashlight, a pitchfork, a shotgun and shells, planks and nails, traps, bandages), and in the world the host's panel can give it again, set the clock to dawn, noon, dusk or night, and spawn enemies near you (dogs, chompers, a centipede, a kamikaze, a human spider). Save the world after the area is built: if none of it is there on the next load, it's built again. Host it and friends join it as any hosted world. It has been built and checked by the host only, not yet played by two people, and some things can land inside walls.

## Reading the game's code

`ilspycmd -p -o <dir> <game>/Darkwood_Data/Managed/Assembly-CSharp.dll`, run with `DOTNET_ROLL_FORWARD=Major` for ilspycmd 8.2. Never commit decompiled code.
